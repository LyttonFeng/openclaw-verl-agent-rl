Committee-Reward Agentic RL + mem0 — qwen3.5-4b meeting analysis

Summary of progress & problems · 2026-06-20 · benchmark = Val3 (advisory_stakeholders / gov_speaker_summary / tech_action_items) · eval = heterogeneous committee pairwise (deepseek-chat / qwen3-max / MiniMax-M3, order-consistency + deliberation + sign-test) · inference = transformers shim (tf_shim_batched), NOT vLLM for adapters.

One-paragraph state. Core story is solid and paper-ready: a stable heterogeneous committee reward (RULER-style relative) + the finding that mem0-as-harness ≈ RL as a vehicle for in-distribution signal, with policy-gated RL giving a directional tech win. This session pushed three new questions and got mostly clean negatives that sharpen the story: synthetic data doesn't transfer; mem helps only when Val3-grounded + well-curated; and a committee-only RL round on a swapped mem regressed.

1. Established core findings (paper-ready)

  • Committee reward works & is stable: 3 heterogeneous judges, pairwise + order-consistency + deliberation + sign-test. Judge stability measured: deepseek-chat & qwen3-max std=0.000, minimax ~0.02.
  • Automated-grader blindness: deterministic rule graders have phrasing-sensitive false-negatives + are blind to verbosity/padding; the committee catches what automated metrics miss.
  • mem0-as-harness ≈ RL: injecting generic how-to hints (zero training) gives a directional lift comparable to RL on the dimensions RL can move.
  • policy-gated RL: cold-start base + policy-gated mem gave a directional tech win (historically ~7:1) via gating, not gradient. Magnitude is small & sample-noisy throughout (the project-wide caveat).

2. This session — new experiments & results

2a. Synthetic data (H-E) does NOT transfer to Val3 — decisive negative

Built a generator for "completable + instance-specific" hard action-item tasks (implicit owners, retraction, revised deadlines). Despite the strongest training gradient in the project (within-group key-score std 0.172), neither RL nor mem distilled from H-E transferred to Val3:

  • RL on synthetic H-E → Val3 committee tie/base-lean (no transfer).
  • Mem distilled from synthetic H-E → base+mem ties pure base on tech (dead even), hurts held-out.

Conclusion: in-distribution signal moves Val3; out-of-distribution synthetic does not — via either RL or memory.

Findings: (1) SOURCE matters — Val3-grounded mems revive the advisory lean that the OOD captree mem lost. (2) mem is real, not useless — the old curated mem reproduces its historical ~7:2 advisory lean (8:2) + gov 4:1 under matched conditions. (3) CURATION also matters — old curated > new diff-grounded; the right non-obvious hint ("separate speakers / notable quotes") beats an over-specified one. Best lever on this substrate = a well-curated Val3-grounded mem (directional adv+gov gain), NOT RL.

2c. Capability tree reframed the mem lever (then RL broke it)

The capability_tree_v2_clean.json (built from qwen4b-vs-pro trajectory diff + committee gap) showed mem can only address 4 fix_lever=memory agentic-process capabilities (deliverable_emission [weakness 0.819], effort_calibration, tool_error_recovery, search_termination); output_content_correctness is fix_lever=weights (RL-only). The earlier content mem failed partly because it aimed at the weights lever. The captree process mem cut timeouts (mechanical win) but did not give a significant in-dist quality win.

captree-gated committee-only RL (r1) REGRESSED all 3 tasks: advisory/gov produced 0 valid deliverables (no-deliverable), tech base+mem beat r1 8:2. Mechanism: committee reward → verbosity/overwork → broke deliverable emission on long tasks. Swapping the mem into the proven gated recipe did NOT reproduce the tech-7:1 win — the win is a fragile mem×reward×task combination.

3. Problems encountered

  • tf_shim is slow & fragile (the dominant time sink). Transformers backend (no paged-attention/continuous-batching) is ~10× slower than vLLM; long agentic rollouts (e.g. 206KB Tampa transcript, 44 tool-call turns) exceed the wall-clock budget. Most wall-time this session went to harness reliability, not science.
  • Timeouts as a confound: long tasks (council_votes, NASA-ledger) time out even at MULT 6 (1080s) → empty deliverables that look like "mem hurts" but are backend artifacts. Always separate timeout from quality. Healthcheck (drop all-dead groups) is essential before training.
  • Backend comparability: vLLM (non-think template + qwen3_coder parser) ≠ tf_shim output distribution → must NOT mix backends across a comparison. All measurements kept on tf_shim.
  • Chain bugs (fixed): NASA-ledger groups all-timeout → drop to 7 healthy groups; ${INIT:+LORA_ADAPTER=$INIT} expanded to a literal command (use explicit export LORA_ADAPTER); local RUN=.. ROLL=$RUN/.. on one line is unbound under set -u; advisory goes all-dead at r2 under the r1 policy → drop advisory (matches the original recover_gated_r2).
  • mem circularity: a mem distilled by "summarize good base outputs" feeds base its own competence → no gain. Extract from the gap (strong-ref vs base, or committee critique), not from success.
  • Significance vs direction: at N=9–12 pairwise, almost everything is "TIE" by sign-test; only consistent, reproduced leans are trustworthy. Magnitudes are small project-wide.

4. Bottom line & next

On these (near-saturated for the 4B base) Val3 tasks, the reliable lever is a well-curated, Val3-grounded mem (directional adv+gov gain) — not RL, which regressed here. The core paper story (committee reward + automated-blindness + mem0≈RL + gated-RL) stands; this session adds strong ablations: mem transfers only with in-distribution grounding + correct curation; synthetic generation doesn't transfer; committee-only RL can break deliverable emission via verbosity. Future work: try harder/under-saturated substrates where base genuinely fails (mem/RL have headroom there), and a reward that penalizes no-deliverable/verbosity.
